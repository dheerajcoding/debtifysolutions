# AI Coding Rules — Save Credits

## Before Starting
- Read and follow this file before working.
- Inspect only files relevant to the task.
- Check existing code before creating anything new.
- Do not scan the entire project for small tasks.

## Save AI Tokens and Credits
- Be concise. Avoid long explanations unless requested.
- Do not repeat information already provided.
- Do not regenerate unchanged files or code.
- Avoid unnecessary planning, searches, tool calls, and repeated file reads.
- Use the smallest relevant context possible.
- Do not perform unrelated improvements.

## Code Changes
- Make the smallest complete change that solves the task.
- Edit only necessary files.
- Reuse existing components, functions, styles, and dependencies.
- Do not rewrite entire files when a small patch is sufficient.
- Preserve existing features, UI, styling, routes, APIs, and behavior.
- Follow the existing project architecture and coding conventions.
- Do not install packages unless genuinely necessary.

## Debugging
- Identify the root cause before changing code.
- Inspect relevant error messages and configuration first.
- Do not repeat failed commands without a new reason.
- Test the smallest affected area first.
- Run broader tests only when necessary.
- Never claim that something works unless verified.

## Safety
- Never delete working code or user data unnecessarily.
- Never overwrite unrelated user changes.
- Do not expose secrets, API keys, tokens, or .env values.
- Ask before destructive operations, expensive API calls, or major architectural changes.
- Do not change database schemas or dependencies without a clear need.

## Workflow
1. Understand the requested task.
2. Inspect only the necessary files.
3. Make minimal, targeted changes.
4. Verify the result where practical.
5. Report what changed and what was tested in a few lines.

## Scope
- Do exactly what the user asks.
- Do not add unrequested features.
- If important information is missing, ask one concise question.
- If a task is large, divide it into focused steps.
- Prioritize correctness, minimal token usage, and preservation of existing functionality.
